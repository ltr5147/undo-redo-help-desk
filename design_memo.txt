Design Memo

A stack is the right choice for an undo and redo system because it follows the last in, first out order. The most recent action is always the first action that should be undone. When an action is performed, it is pushed onto the undo stack. Undo removes the top action and pushes it onto the redo stack. Redo reverses that process by moving the most recently undone action back to the undo stack. Performing a new action clears the redo stack because the earlier sequence of undone actions is no longer part of the current editing history.

A queue is better for the help desk because it follows first in, first out order. The customer who submits a ticket first should normally receive help first. Enqueue adds each new customer at the rear, while dequeue removes the customer at the front. Keeping both front and rear pointers makes these two operations efficient. The queue also allows an agent to peek at the next customer without removing that person.

My implementations differ from Python's built-in lists because they use linked Node objects instead of numbered indexes in one built-in container. Each node stores a value and a pointer to the next node. The Stack keeps a top pointer, while the Queue keeps both front and rear pointers. This limits access to the operations appropriate for each structure and makes their behavior clear. Adding or removing at these pointer locations takes constant time and does not require shifting other values. However, linked structures use extra memory for pointers and do not provide the direct indexed access available with Python lists. Building them manually provides more control but also requires careful handling of empty structures and pointer updates.
